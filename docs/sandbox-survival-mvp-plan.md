- [x] M0 基础设施就绪

## 1. 目标与范围

周期：2026-02-09 到 2026-02-15（7天）

目标：交付 Web 单人第一人称固定种子世界的“可玩闭环”

范围内：
- 第一人称移动与视角控制
- 固定种子世界初始化与分块加载（小半径）
- 采集、放置、背包快捷栏
- 生存四指标：生命、饥饿、温度、耐久
- 本地存档与读档
- 容器化自动测试（typecheck + unit + integration + e2e）

范围外（本周不做）：
- 多人联机
- 敌对 AI
- 复杂刚体堆叠/破坏
- 跨端适配优化

## 2. 里程碑与验收标准

### M0（已完成）基础设施就绪
验收：
- `sandbox-survival` 工程可启动
- `bash scripts/test-in-container.sh --app-dir sandbox-survival` 通过
- 产物落盘到 `artifacts/container/sandbox-survival/`

### M1（Day 1-2）可控场景
交付：第一人称移动、视角、地面碰撞、最小 HUD
验收：
- E2E 可稳定进入场景并完成移动操作
- 帧率目标：测试环境 20 FPS+（llvmpipe），本地尽量 30 FPS+
- 无阻塞级崩溃（启动 20 次连续成功）

### M2（Day 3）交互闭环
交付：采集 2 类资源，放置 2 类建造件，快捷栏
验收：
- 单局流程“采集 -> 放置 -> 再采集”可重复
- 关键状态在 UI 可观察（库存数量、选中槽位）
- 单元测试覆盖核心库存与放置规则

### M3（Day 4）生存系统
交付：生命/饥饿/温度/耐久联动
验收：
- 饥饿归零会触发生命下降
- 温度过低触发持续伤害，热源可恢复
- 工具耐久耗尽不可继续采集

### M4（Day 5）存档系统
交付：世界差异 + 玩家状态本地存取
状态：已完成（2026-02-07）
验收：
- 存档后重开可恢复：位置、库存、已放置对象、生存指标
- 读档失败有回退策略（不崩溃，提示并重建默认档）

### M5（Day 6-7）联调与冻结
交付：测试补齐、参数调优、演示构建
状态：已完成（2026-02-07）
验收：
- 容器测试全绿
- 至少 1 条 E2E 覆盖完整玩法闭环
- 发布说明记录已知风险与后续项

## 3. 并行开发拆分（可独立推进）

并行流 A：`World/Render`
- 负责人：引擎与渲染
- 模块：`src/world/*`, `src/render/*`
- 接口输出：`WorldState`, `ChunkEvents`

并行流 B：`Gameplay/Survival`
- 负责人：玩法逻辑
- 模块：`src/gameplay/*`, `src/survival/*`, `src/inventory/*`
- 接口输入：玩家位置、交互事件
- 接口输出：状态变化与 UI 数据

并行流 C：`Persistence/QA`
- 负责人：存档与测试
- 模块：`src/persistence/*`, `tests/*`, `scripts/*`
- 接口输入：可序列化快照
- 接口输出：回归结果与报告

并行边界原则：
- 使用事件/数据契约，不跨模块直接改内部状态
- 每日合并窗口 2 次，避免长期分叉
- 每条并行流必须带测试，不接受“先代码后补测”

## 4. 验收指标（Definition of Done）

功能指标：
- MVP 闭环可演示：移动、采集、放置、生存消耗、存档恢复

质量指标：
- 容器链路全绿
- 单元 + 集成 + E2E 均存在且稳定
- 关键玩法路径无 P0/P1 缺陷

性能指标：
- 测试环境（xvfb + firefox + llvmpipe）20 FPS+
- 启动到可操作时间 < 5 秒（容器环境）
